# Purpose

This document defines the recommended order in which Explorer Academy documentation, architecture and implementation should be created.

It exists to ensure that:

- foundational thinking precedes implementation
- architectural consistency is preserved
- AI contributors work in dependency order
- future contributors understand the project's maturity
- implementation begins only after the architecture is sufficiently stable

This roadmap is the project's build plan.

---

# Guiding Principle

**Never build the thing before defining how it should work.**

# Roadmap Rules

- Never skip stages.
- Complete dependencies first.
- Review architecture before implementation.
- Update this roadmap whenever milestones change.

---

# Success Metric

The roadmap is complete when future campaigns require primarily new content—not new platform code.
